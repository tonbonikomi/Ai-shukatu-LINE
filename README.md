# Ai-shukatu-LINE

株式会社AI就活の、公式LINE「一柳」を使った紹介制の就活生コミュニティに関するリポジトリ。

**実装は別途、本番稼働している**（2026-09 時点）。
一柳のチャネル・登録ページ（LIFF）・入口リンク・グループ振り分け・入室検知・
運営ダッシュボードまで作られ、既存の送客管理と同じプロバイダーに置かれているため
LINEのユーザーIDも揃っている。

このリポジトリは**設計と運用のドキュメントを残す場所**として使う。
`src/` と `supabase/` は本番稼働しているものとは別系統の参考実装であり、
**運用では使わない**（[経緯](#実装について)）。

## 開発

```bash
npm install
cp .env.example .env.local     # 値を埋める
npm run dev                    # http://localhost:3000/register

npm run check                  # 型チェック + ユニットテスト + DBテスト
```

| コマンド | 内容 |
|---|---|
| `npm run typecheck` | TypeScript の型チェック |
| `npm run test` | ユニットテスト（vitest） |
| `npm run test:db` | 空のDBにマイグレーションを流してSQLのテスト |
| `npm run build` | 本番ビルド |

### 構成

```
src/
├── app/
│   ├── register/                  登録画面（LIFF）
│   └── api/
│       ├── invite/[token]/        入口リンクの検証
│       ├── register/              登録の受付
│       └── line/webhook/          LINE からの通知の受け口
├── lib/
│   ├── domain/                    卒業年度の計算・入力検証・トークン生成
│   ├── line/                      署名検証・イベント振り分け・送信
│   ├── liff/                      IDトークンの検証
│   └── db.ts                      Postgres への直接接続
└── server/                        登録処理・入室検知・運営通知・文面
supabase/                          マイグレーションとSQLのテスト
```

判断が入るところ（卒業年度の計算・署名検証・イベントの振り分け・入力検証）は
`src/lib` の純粋な関数に切り出してあり、テストで固定してある。

## 実装について

`src/`（Next.js）と `supabase/`（マイグレーション・SQLテスト）は、
本番とは**別系統の参考実装**。本番実装が先に完成したため、運用では使わない。

読む価値が残っているのは次の2点。

- `supabase/migrations/` — 招待トークン・グループ台帳・入室ログのスキーマ設計と、
  そこに込めた制約（受付中グループは卒年×地域で1つ、`member_count` は毎回再計算、など）
- `tests/graduation.test.ts` — 卒業年度の計算。**年度の判定をJSTで行わないと3/31と4/1の境界で
  1年ずれる**という落とし穴を、境界のテストで固定してある

## 調査で判明した重要事項

**グループへの投稿は、メンバー人数分の通数としてカウントされる**（1通ではない）。
500人グループへの1投稿 = 500通。構想メモ §8-3 の「1通ならグループ投稿を告知の主役にできる」という
前提は成立しないため、投稿頻度の上限を運用ルールとして先に決める必要がある。
一方で応答メッセージ（reply）は無料なので、1対1の詳細案内は組み方次第でコストをかけずに回せる。

詳細は [調査結果](docs/line-platform-research.md) を参照。
