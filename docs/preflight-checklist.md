## B. 実装のブロッカー（これが無いとコードを書き始められない）

| # | やること | 補足 |
|---|---|---|
| B-1 | LINE Developers コンソールへのアクセス権を実装側に渡す | 閲覧だけでも可。まずプロバイダー構成が見たい |
| B-2 | **既存就活DBのプロバイダー名を特定** | 送客管理LIFF `2010483281-…` がどのプロバイダー配下か |
| B-3 | **一柳の Messaging API チャネルを作成** | ⚠ B-2 と**同じプロバイダー**に。後から変更できない |
| B-4 | **一柳ログイン（LINEログイン）チャネルを作成** | ⚠ 同上。LIFF のホストになる |
| B-5 | 料金プランをスタンダードに設定 | 30,000通/月。グループ投稿は人数分カウントされるため |
| B-6 | 応答モード=Bot / 自動応答メッセージOFF / あいさつは1対1のみ | グループでの誤爆を防ぐ（設定側の1枚目のガード） |

> **B-3 / B-4 でプロバイダーを間違えると全部作り直しになります。**
> LIFFで取得する userId と webhook の userId はプロバイダー単位で発行されるため、
> 別プロバイダーだと登録者とグループ入室者を照合できず、構想の土台が崩れます。
> チャネル作成後、テストユーザー1名で両者が一致することを実際に確認してから実装に入ります。

```
A-1 認証申請 ──────────────────(5〜10営業日)──────→ 定期棚卸しが使えるように
A-2 弁護士 ────────────────────(数週間)──────────→ 紹介料の支払い開始
A-3 業務用番号 ──→ 業務用LINE作成 ──→ E-1 と合流 ──→ グループ作成

B-2 プロバイダー特定 ──→ B-3/B-4 チャネル作成 ──→ userId一致テスト
                                                        │
                                                   ここが通ってから実装開始
                                                        │
                                              C（認証情報）と合流 ──→ 実装
```

**A の3件は今日出せて、出さないと後で待つことになります。**
B は実装開始のブロッカー、C は実装中に必要、D と E は最初のグループを開ける前まででかまいません。
