# 用語集

このプロジェクトの資料に出てくる言葉。エンジニアでなくても読めるように書いてある。
「LINEの言葉」「このプロジェクトの言葉」「基盤の言葉」の3つに分けてある。

---

## LINEの言葉

### LIFF（リフ）
**LINEアプリの中で開くWebページ。** LINE Front-end Framework の略。

普通のWebページとの違いは1点で、**開いた人が誰なのかがページ側で分かる**こと。
普通のフォームは誰が送信したか分からないため、メールアドレスを聞いて後で突合する手間が要る。
LIFFはLINEの中で開くので、開いた瞬間にその人のLINEユーザーIDが取れる。ログイン操作も要らない。

**このプロジェクトでの役割**: 登録画面がこれ。入口リンクを踏むとLIFFが開く。
「30秒で登録が終わる」「誰の紹介で登録したかが確実に記録される」の両方がLIFFで成立している。

> 既存の送客管理でも使っている。構想メモの `2010483281-…` がそのLIFF ID。

### LIFF ID
`2010483281-abcdefgh` のような文字列。LIFFアプリ1つにつき1つ発行される。
URLは `https://liff.line.me/{LIFF_ID}` になり、**これが入口リンクそのもの**。

> ⚠ **LIFFアプリを作り直すとIDが変わり、配布済みの入口リンクが全て死にます**（[D-004](decisions.md#d-004)）。

### エンドポイントURL
LIFFが実際に表示するWebページのURL。自分で用意してホスティングする。

**LIFF IDは固定のまま、エンドポイントURLは差し替えられる。**
つまり登録画面の中身・項目・デザインは何度でも作り直せる。変えられないのはLIFF IDだけ。

### プロバイダー
チャネル（後述）をまとめる入れ物。**「どの事業者のものか」を表す単位。**

重要なのは、**ユーザーIDがプロバイダーごとに発行される**こと。
同じプロバイダーの中では同じ人に同じIDが振られ、プロバイダーが違えば違うIDになる。
**チャネルのプロバイダーは後から変更できない。**

これが構想メモ §8-1 が最優先である理由。一柳とLIFFが別プロバイダーだと、
LIFFで登録した田中さんと、グループに入ってきた田中さんが同一人物だと分からなくなる。

### チャネル
LINEの機能を使うための「口」。用途ごとに種類がある。このプロジェクトでは2つ使う。

| チャネル | 役割 |
|---|---|
| **Messaging API チャネル** | 一柳。トークでメッセージを送受信する側 |
| **LINEログイン チャネル** | LIFFの入れ物。登録画面を表示する側 |

**この2つは同じプロバイダーの下に置く必要がある**（上記の通り）。

### 認証済みアカウント
LINEの審査を通った公式アカウント。緑の認証バッジが付く。申請は無料、審査は5〜10営業日。
**申請中も運用は止まらない。**

このプロジェクトで効いてくるのは、**グループのメンバー一覧を取得するAPIが認証済み限定**である点。
未認証だと、通信が止まっていた間に入った人を後から棚卸しできない。

### webhook（ウェブフック）
**LINEで何かが起きたときに、こちらのサーバへ自動で届く通知。**
「友だち追加された」「メッセージが来た」「グループに人が入った」などが飛んでくる。

このプロジェクトの入室検知は、これで実現している。人が見張っているわけではない。

### memberJoined / memberLeft
webhookの一種。**グループに人が入った／出た**ときに届く通知。
誰が入ったか（ユーザーID）が含まれるので、名簿と照合できる。

### プッシュメッセージ / 応答メッセージ
| 種類 | 何か | 通数 |
|---|---|---|
| **プッシュメッセージ** | 運営側から一方的に送るメッセージ | **課金される** |
| **応答メッセージ** | ユーザーの発言に対して返すメッセージ | **無料** |

この違いがコスト設計の要。「参加希望の方は『0904大阪』と送ってください」という形にすると、
以降のやりとりが全て応答メッセージになり無料で回る。
一方、前日リマインドのように運営から一方的に送るものは課金される。

### 通数（メッセージ通数）
料金の単位。**送った相手の人数**で数える。1回の送信で何個のメッセージを含めても関係ない。

**グループ投稿はメンバー人数分カウントされる。** 500人グループへの1投稿＝500通。
詳細は [LINEプラットフォーム調査結果](line-platform-research.md)。

### マルチキャスト
複数の相手に個別に同じ内容を送ること。属性で絞った案件配信に使う。
対象50人なら50通。グループ投稿（400人なら400通）より桁で安い。

### 応答モード
公式アカウントの設定。「Bot」にすると、自動応答が止まってこちらのプログラムに制御が渡る。
**グループでの誤爆を防ぐ1枚目のガード。**

### replyToken（リプライトークン）
webhookに付いてくる「この発言に返信するための引換券」。
これを使って返すと応答メッセージ扱いになり**無料**。1つのイベントにつき1回だけ使える。

### IDトークン
LIFFが発行する「この人は確かにこのLINEユーザーです」という証明書。
サーバ側でLINEに問い合わせて検証してから使う。

**クライアントが送ってきたユーザーIDをそのまま信じてはいけない**（なりすまし対策）。

### リッチメニュー
トーク画面の下に固定表示されるメニュー。タップでLIFFを開いたりできる。
入口リンクを自動発行に切り替えるとき、「友達を誘う」をここに置けば通数を使わずに配れる。

### OpenChat（オープンチャット）
LINEの別種のグループ機能。**botが入れないため自動化できず、今回は却下**（構想メモ §9）。

## このプロジェクトの言葉

### 一柳（いちやなぎ）
このコミュニティで使う公式LINEアカウント。**既存の送客管理用アカウントとは別物。**

登録の受付、グループ招待リンクの送信、入室の検知、1対1の応答を担当する。

### 入口リンク
**招待したい学生が友達に配るリンク。** `https://liff.line.me/{LIFF_ID}?t={トークン}` の形。

タップすると一柳の友だち追加と登録画面に進む。URLに紹介者を示すトークンが埋まっているので、
**誰の紹介で登録したかが自動で記録される。**

運営が発行し、いつでも無効化できる（[D-001](decisions.md#d-001)）。

### グループ招待リンク
**LINEグループそのものへの参加リンク。入口リンクとは別物。**

**一柳だけが持ち、登録を完了した人にだけ自動で送る。** 招待する側には渡さない。
渡すとコピペで無制限に転送され、誰が入ったか把握できなくなるため。

### 招待トークン
入口リンクのURLに埋まっている文字列。誰の紹介かを表す。
発行・無効化ができる。既存の `partners.ref_code` は取り消せないので使わない。

### 招待したい学生
友達を誘いたいコミュニティ参加者。運営が入口リンクを発行する相手。

> 資料や文面では「エージェント」「代理店」という語を使わない（kaz指示 2026-08-26）。

### 紹介者
その人を連れてきた人。全登録者に紐づく。悪い紹介者を特定して止められるのはこれがあるから。

### ティア
紹介者の等級。良い人を連れてくれば上がって単価が上がり、荒らせば下がる。
既存の `payout_rates` の仕組みに乗る。**運用データが溜まってからの後付け。**

### 素行スコア
ドタキャン・無断欠勤・グループ内での勧誘などの記録。紹介者のティアに反映される。
運営が審査する代わりに、紹介した側の経済合理性に判断を埋め込むための仕組み。

### 棚卸し
グループの実際のメンバーと、こちらの名簿を突き合わせて差分を直す作業。
**認証済みアカウントが前提。** 週1回程度を想定。

### 即払い
案件ごとに設定できる報酬の即時支払い。既存の仕組みがそのまま使える。
基本は月末払いで、必要な案件だけONにする。

## 基盤の言葉

### Supabase（スーパベース）
データベースとその周辺機能をまとめて提供するサービス。既存の送客管理でも使っている。
登録者・グループ・紹介者などの情報はここに入る。

### n8n（エヌエイトエヌ）
処理の流れを画面上でつないで自動化するツール。既存基盤で稼働中。
このプロジェクトでは**通知の配線と定期実行**に使う想定。

### Edge Functions
Supabase上で動かすプログラム。webhookの受信や登録処理など、
**判断が必要なロジック**はこちらに置くことを推奨している（テストとレビューができるため）。

### RLS（行レベルセキュリティ）
「誰がどの行を読み書きできるか」をデータベース側で強制する仕組み。
個人情報を持つので、外部から直接読めないよう全テーブルで有効にする。

### マイグレーション
データベースの構造を変更する手順を、実行できる形で記録したもの。
本番と開発で同じ構造を再現するために使う。

### webhook署名検証
届いたwebhookが本当にLINEから来たものかを確認する処理。
これをやらないと、偽の「入室しました」通知を外部から送り込めてしまう。
